# ADR-0003: Critic 质量门控与回退终止策略

**状态**：已接受  
**日期**：2026-07-27  
**决策人**：[姓名]

## 背景

Critic Reviewer 负责在最终输出前拦截伪根因。若 Critic 过于保守，会误拦截真实根因，导致反复回退、延迟升高；若过于激进，会放过伪根因，降低系统可信度。需要明确：

1. Critic 自身的质量指标如何定义；
2. 被驳回后 Orchestrator 如何回退；
3. 回退何时终止，终止后如何输出。

## 决策

1. Critic 同时优化两个指标：
   - **伪根因召回率 ≥ 80%**（Critic 成功拦截的伪根因 / 全部伪根因）；
   - **真根因误拦截率 ≤ 10%**（Critic 错误驳回的真根因 / 全部真根因）。
2. 单次诊断最多允许 **2 轮回退**（含 Ranker 重排与 Judge 补链）。
3. 达到回退上限仍未通过 Critic，输出当前最优候选 + 不确定性说明，并标记 `needs-human-review`。

## 理由

- **单一指标会作弊**：仅看“拦截率”可能通过过度驳回达成，损害真根因通过率。双指标约束更稳健。
- **2 轮回退是延迟与质量的折中**：每轮回退增加 Judge/Ranker 调用，P99 预算 30s。2 轮后仍不收敛，说明证据不足或策略缺陷，应转人工。
- **明确失败输出**：避免系统在回退循环中无限消耗资源，同时给运维人员可行动的提示。

## 后果

### 正面

- Critic 目标可量化，便于 Evaluator 回归与 GEPA 优化。
- Orchestrator 状态机有明确终止条件，避免级联超时。
- 人工介入点清晰，便于设计工单/告警工作流。

### 负面

- 2 轮可能不足以覆盖某些复杂多根因场景；若实际误拦截率高，需放宽次数或改进 Critic。
- `needs-human-review` 标记会引入人工队列，需配套 SLA。
