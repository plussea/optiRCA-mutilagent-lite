# PRD：OptiRCA Lite 高级诊断大屏

**版本**：v1.0  
**日期**：2026-08-10  
**状态**：待实现  
**范围**：前端诊断结果展示页高级化重构（不改动后端诊断算法）

---

## Problem Statement

当前前端诊断结果页采用传统的“上传 → 报告 → 切换标签页”表单式布局，与光网络 NOC 运维场景的专业性、紧迫性不匹配：

- 结论与证据图分离在不同标签，运维人员难以一眼把“根因是什么”和“为什么是它”关联起来。
- 节点为抽象圆角卡片，缺乏网络设备质感，无法快速建立物理直觉。
- Agent 流程被折叠在第二个标签页里，推理过程不可见，难以建立信任。
- 人工审核入口与成功结论混排，没有根据风险等级进行视觉分级。
- 缺少逐阶段回放能力，专家复盘时只能看到最终结果。

## Solution

将诊断结果页升级为**专业光网络运维大屏**：

1. **全屏画布优先**：证据拓扑作为唯一主视觉，占据全部可用空间；Agent 流程不再以标签页形式存在，而是压缩为顶部结论条下方的**阶段播放时间轴**。
2. **拟物设备节点**：设备、端口、链路采用中等拟物的工业控件风格，告警以附着在红点的形式出现在节点上，点击后展开详情。
3. **固定顶部结论条**：始终显示根因、置信度、状态；当需要人工审核时，顶部条变为琥珀色并出现明确审核 CTA。
4. **右侧详情抽屉**：默认展示诊断结论摘要、证据链、处置建议；选中节点/边/告警后切换为对象级详情；需要审核时在底部露出审核操作。
5. **阶段播放与伪回放**：顶部时间轴展示感知 → 拓扑 → Judge → Rank → Critic → 组装六个阶段；后端未来支持 SSE/流式，当前先实现前端伪回放，可拖动、暂停、重播。
6. **暗色工业配色**：深蓝灰背景、蓝白高亮、琥珀色风险、红色告警，保持长时间监控场景下的可读性。

## User Stories

1. 作为 NOC 值班工程师，我希望上传 CSV 后第一眼就看到设备拓扑上的根因高亮，以便在 10 秒内确认故障位置。
2. 作为 NOC 值班工程师，我希望顶部始终显示结论和置信度，不需要滚动或切换标签，以便在告警风暴中快速决策。
3. 作为运维专家，我希望点击链路上的告警红点即可查看原始告警字段，以便验证系统推断。
4. 作为运维专家，我希望通过阶段时间轴回放诊断过程，以便理解 Agent 为什么得出该结论。
5. 作为运维专家，我希望当 Critic 要求人工审核时，顶部条和右侧面板同时变琥珀并给出“批准/驳回/升级”入口，以免漏掉关键决策。
6. 作为算法工程师，我希望选中候选根因节点后右侧面板展示评分拆解，以便判断 Ranker 权重是否合理。
7. 作为新接入团队成员，我希望界面风格与专业网管平台一致，降低学习成本。
8. 作为产品经理，我希望 Demo 运行后自动进入回放状态，方便向客户展示完整诊断叙事。
9. 作为值班主管，我希望在非审核状态下审核入口不抢占视觉焦点，避免误操作。
10. 作为前端开发者，我希望新界面继续使用 React Flow 作为图引擎，减少引入新依赖的风险。
11. 作为测试人员，我希望每一阶段回放结束后对应节点/边高亮状态可断言，以便做 E2E 验证。
12. 作为后端开发者，我希望前端先实现伪回放，不阻塞后端真正 SSE 的实现。

## Implementation Decisions

1. **布局结构**
   - 无左侧边栏；顶部固定结论条 + 阶段时间轴，中间全屏画布，右侧可折叠详情抽屉。
   - 右侧抽屉默认宽度 360px，折叠后只留一个展开把手；在 ≤1280px 时自动变为浮层。

2. **画布与图引擎**
   - 继续使用 `@xyflow/react` 渲染异构证据图。
   - 新增自定义节点类型：`DeviceNode`（机框风格）、`PortNode`（端口面板）、`LinkNode`（线缆）、`AlarmDot`（附着告警）。
   - 边采用平滑曲线，颜色按类型区分：`TOPOLOGY` 蓝灰实线、`BELONGS_TO` 虚线、`PROPAGATES` 红色发光虚线。
   - 根因链路与节点在回放完成后以脉冲光晕高亮。

3. **阶段时间轴**
   - 时间轴位于顶部结论条下方，高度 56px，显示 `感知 → 拓扑 → Judge → Rank → Critic → 组装` 六个阶段节点。
   - 每个阶段有 `idle / running / done / error` 四种视觉状态。
   - 点击阶段可跳转到该阶段结束时刻并重绘画布状态；支持播放、暂停、重播、进度拖动。
   - 当前实现为**前端伪回放**：根据 `DiagnosisResult.metadata.phases_completed` 和 `degradation_reason` 生成离散阶段事件序列；未来替换为后端 SSE 流式事件。

4. **右侧详情抽屉**
   - 默认视图：状态徽章、根因摘要、置信度、证据链文本、处置建议、Critic 复核结论。
   - 对象视图：选中节点/边后展示该对象的属性、关联告警、置信度、在传播链中的角色。
   - 审核视图：当 `requires_human_review=true` 时，默认视图底部出现审核卡片，包含 `approved / rejected / escalated` 三个按钮和备注输入框；顶部结论条同步变琥珀色。

5. **视觉设计系统**
   - 背景：`#0b1120` → `#111827` 径向渐变；网格线 faint。
   - 设备节点：深色金属质感边框、蓝青色指示灯、设备类型图标。
   - 告警点：红色圆点 + 脉冲动画；Critical 用 rose-500，Major 用 amber-500，Minor 用 blue-400。
   - 文本：主要 `#e2e8f0`，次要 `#94a3b8`，高亮 `#38bdf8`，风险 `#f59e0b`。
   - 字体继续使用系统无衬线 + 等宽字体用于技术字段。

6. **交互状态**
   - 画布节点 hover 时放大 1.05 并显示标签 tooltip。
   - 选中节点后其他非关联元素降低透明度至 0.35。
   - 回放过程中，阶段时间轴当前阶段下方的画布逐步揭示：先拓扑边，再告警点，最后根因高亮。

7. **数据契约**
   - 不改变现有 `POST /api/v1/diagnose` 响应结构；新增消费字段：`metadata.phases_completed`、`requires_human_review`、`degradation_reason`、`critic_verdict`。
   - 前端内部构建一个 `PlaybackEvent[]` 中间层，把后端结果转换为时间轴可消费的离散事件，便于未来接入 SSE 时只替换数据源。

## Testing Decisions

- 主要 seams：组件渲染（RTL + Jest/Vitest）、用户交互（点击节点/阶段）、E2E 关键路径（Playwright 或 Vercel Agent Browser）。
- 单元测试覆盖：时间轴状态机、`PlaybackEvent` 生成逻辑、自定义节点渲染。
- E2E 覆盖：上传 CSV → 进入结果页 → 时间轴自动播放 → 根因节点存在 → 点击告警点打开详情 → 审核状态正确显示。
- 不测试 React Flow 内部布局算法，只测试传入的 nodes/edges 是否符合预期。
- 视觉回归暂不做，但关键颜色/状态类名保留稳定的 `data-testid` 供 E2E 断言。

## Out of Scope

- 后端真正的 SSE/流式诊断阶段推送（当前用前端伪回放占位）。
- 3D 拓扑或 GIS 地图可视化。
- 拓扑自动布局算法的大规模优化（先使用简单分层 + 力导向）。
- 新的后端 API 或数据 schema 变更。
- 多根因同时高亮（仍按当前单根因处理）。
